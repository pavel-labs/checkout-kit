# Платёжная страница банка

> English version: [plugins/hosted-page.md](../../plugins/hosted-page.md)

`@checkout-kit/provider-hpp` — id `hpp`

Покупатель уходит с вашего сайта на страницу самого банка, платит там и возвращается. Ваш код
карту не видит вообще никогда.

**Берите этот, если** хотите минимально возможный PCI-след и готовы уводить покупателя. Это
самый простой вариант из всех здесь и тот, что меньше всего оставляет вас на пути карты.

## Что видит покупатель

1. Жмёт «Оплатить». Полей карты на вашей странице нет — заполнять нечего.
2. Вся вкладка уходит на страницу банка.
3. Он платит там, включая любое подтверждение.
4. Банк возвращает его на ваш return URL.
5. Ваш чекаут подхватывает платёж и показывает исход.

## Одна вещь, которую обязательно надо сделать правильно

**Шаг 4 уничтожает вашу вкладку.** Всё, что было в памяти, пропало. Когда покупатель
возвращается, чекаут должен найти платёж заново — это `hydrate()`, и без него этот плагин умеет
начать платёж, но не умеет его завершить:

```ts
// На роуте, куда указывает ваш returnPath.
useEffect(() => {
  void engine.hydrate(runtime.readReturnParams())
}, [engine])
```

Перед редиректом движок записал в session storage всё, что нужно. `hydrate` читает это обратно,
берёт параметры, которые банк положил в URL, и спрашивает провайдера, что произошло на самом
деле.

## Он не верит возвратному URL

Банк возвращает покупателя на что-то вроде `?status=success`. Покупатель мог набрать это руками.
Поэтому плагин это игнорирует и перечитывает заказ из вашего бэкенда.

Это стоит скопировать, если пишете свой плагин. **Параметр в URL — это утверждение, а не факт.**

## Как подключить

```ts
import type { HostedPageConfig } from '@checkout-kit/provider-hpp'

const hostedPage: HostedPageConfig = {
  // Ваш бэкенд: регистрирует заказы и читает их обратно.
  baseUrl: '/api',
  // Где живёт платёжная форма банка. В продакшене — другой сайт.
  pageUrl: 'https://pay.yourbank.example/checkout',
}

defineProvider({
  id: 'hpp',
  config: hostedPage,
  load: () => import('@checkout-kit/provider-hpp'),
})
```

### Оплата

Карту отправлять нечего, поэтому инструмент — `none`. Это не пропущенное значение, а именно то,
чего ждёт этот провайдер:

```ts
await engine.pay({
  input: { planId: 'monthly' },
  instrument: { kind: 'none' },
  idempotencyKey: crypto.randomUUID(),
})
```

Поля карты для этого провайдера рисовать не надо. Движок сам скажет:

```ts
const { capabilities } = useCheckout()
const collectsCard = capabilities?.instruments.includes('card') ?? true
```

## Что должен уметь ваш бэкенд

| Вызов                     | Что делает                            |
| ------------------------- | ------------------------------------- |
| `POST /hosted/orders`     | регистрирует заказ, возвращает его id |
| `GET  /hosted/orders/:id` | читает исход после возврата           |

## Как попробовать

`npm run dev:mock`, затем выберите «Hosted payment page». Демо подставляет собственную платёжную
страницу, потому что мок, живущий только в браузере, не может отвечать с другого origin — в
продакшене эта страница действительно где-то ещё.

## Что может пойти не так

**Покупатель возвращается в пустой чекаут.** На возвратном роуте не вызывается `hydrate()`. Это
_та самая_ ошибка, и она незаметна, пока не пройдёшь реальный сценарий.

**Локально работает, в продакшене ломается.** Ваш `returnPath` относителен базовому пути
приложения. Если приложение отдаётся с подпути, стройте возвратный URL от этой базы, а не
хардкодьте `/payment/return`.

**Платёжная страница отказывается грузиться во фрейме.** Правильно и намеренно. Этот плагин
объявляет только поверхность `top`: платёжная страница банка не должна вставляться во фрейм,
потому что именно так делают поддельную.

## Что он объявляет

|                |                                                       |
| -------------- | ----------------------------------------------------- |
| инструменты    | `none`                                                |
| действия       | `redirect`                                            |
| поверхности    | только `top`                                          |
| аутентификация | нет, 3-D Secure 1 и 2                                 |
| отмена         | нет — как только он на странице банка, это дело банка |
| поллинг        | да                                                    |
