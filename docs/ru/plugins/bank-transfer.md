# Банковский перевод

> English version: [plugins/bank-transfer.md](../../plugins/bank-transfer.md)

`@checkout-kit/provider-bank-transfer` — id `transfer`

На экране появляется код. Покупатель открывает банковское приложение, сканирует или вводит его и
платит. Через мгновение деньги на месте.

**Берите этот, если** продаёте там, где так и платят, — а это очень большая часть мира: PIX в
Бразилии, UPI в Индии, BLIK в Польше, PromptPay в Таиланде, SPEI в Мексике. На нескольких из этих
рынков он обгоняет карты.

## Что видит покупатель

1. Жмёт «Оплатить». Ни карты, ни редиректа.
2. Появляется QR-код, сумма и строчка с инструкцией.
3. Он открывает банковское приложение и сканирует. На телефоне — тапает по коду, и приложение
   открывается само.
4. Ваш чекаут через секунду-другую замечает это сам и показывает чек.

## Что здесь по-настоящему иначе

**Ничто на странице не может увидеть, что платёж произошёл.** Он происходит в другом приложении,
на телефоне покупателя, возможно вообще на другом устройстве. Ни колбэка, ни сообщения, ни
редиректа.

Поэтому чекаут спрашивает. Раз за разом, пока деньги не придут или код не истечёт. Это и значит
`poll` в конфиге, и для этого плагина он не опция — это единственный способ платежу завершиться.

## Как подключить

```ts
import type { BankTransferConfig } from '@checkout-kit/provider-bank-transfer'

const transfer: BankTransferConfig = {
  baseUrl: '/api',
  // 'qr' — сканировать, 'code' — вводить, 'instructions' — письменные шаги.
  format: 'qr',
  // Ваш текст и ваш перевод; кит формулировок для этого не поставляет.
  instructions: 'Отсканируйте это банковским приложением или скопируйте код в него.',
  // Как часто спрашивать и как долго продолжать.
  poll: { intervalMs: 2000, timeoutMs: 15 * 60 * 1000 },
}

defineProvider({
  id: 'transfer',
  config: transfer,
  load: () => import('@checkout-kit/provider-bank-transfer'),
})
```

Оба значения `poll` — компромисс. Слишком часто — и вы долбите собственный бэкенд за каждого
ожидающего покупателя; слишком длинный таймаут — и брошенные платежи висят открытыми. Две секунды и
пятнадцать минут — разумное начало и значение по умолчанию, если ничего не указать.

### Куда он рисует

Код рисуется inline, в форме, туда, куда покупатель и так смотрит:

```tsx
{
  action?.surface === 'inline' ? (
    <ActionFrame variant="content">
      <PaymentActionHost onSettled={settle} className="ck-action-host" />
    </ActionFrame>
  ) : null
}
```

`variant="content"` подстраивается под код — именно фиксированная высота делает QR-сценарий
похожим на сломанный.

Картинку QR, кнопку копирования и диплинк рисует рантайм, а не React, и стилизуются они классами
`.ck-display__*` из стайлшита UI-кита. Если провайдер отдаёт срок, покажите его через
`<Countdown expiresAt={action.expiresAt} />`.

### Оплата

```ts
await engine.pay({
  input: { planId: 'monthly' },
  instrument: { kind: 'none' },
  idempotencyKey: crypto.randomUUID(),
})
```

## Что должен уметь ваш бэкенд

| Вызов                              | Что делает                            |
| ---------------------------------- | ------------------------------------- |
| `POST /transfer/orders`            | открывает заказ                       |
| `POST /transfer/orders/:id/code`   | отдаёт код, картинку QR и диплинк     |
| `GET  /transfer/orders/:id`        | деньги пришли? — спрашивается в цикле |
| `POST /transfer/orders/:id/cancel` | отменяет                              |

Третий вызывается в цикле, поэтому сделайте его дешёвым. Читайте статус, а не пересчитывайте
заказ.

**Настоящий ответ берите из вебхука провайдера**, а не из поллинга браузера. Поллинг — это как
узнаёт _экран_; то, что платёж реален, — дело вашего бэкенда.

## Как попробовать

`npm run dev:mock`, затем выберите «Bank transfer». В демо есть кнопка, играющая роль банковского
приложения покупателя, — можно посмотреть, как чекаут узнаёт об оплате сам.

## Что может пойти не так

**Он вечно висит на коде.** Ваш `GET` не меняет статус, либо `timeoutMs` длиннее, чем вы думали.
Чекаут делает ровно то, что ему сказали.

**QR не сканируется.** Он должен оставаться тёмным на светлом при любой теме — UI-кит специально
подкладывает под него белый фон. Если перестилизуете, сохраните это.

**Покупатель заплатил после таймаута.** Деньги настоящие, а чекаут уже перестал ждать. Поэтому и
важен вебхук: ваш бэкенд обязан закрыть заказ независимо от того, что успел увидеть браузер.

## Что он объявляет

|                |                                            |
| -------------- | ------------------------------------------ |
| инструменты    | `none` — карта уже есть у банка покупателя |
| действия       | `display`                                  |
| поверхности    | `inline`                                   |
| аутентификация | нет — банковское приложение уже её сделало |
| отмена         | да                                         |
| поллинг        | да, и обязателен                           |
