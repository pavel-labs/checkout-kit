# Как пользоваться платёжными плагинами

> English version: [plugins/index.md](../../plugins/index.md)

Плагин — это та часть, которая знает, как разговаривает один платёжный провайдер. Он создаёт
платёж, отправляет инструмент и говорит, что произошло. Всё остальное — экраны, состояние,
повторная попытка, фрейм, в котором рисует банк, — одинаково, какой бы плагин вы ни выбрали.

Плагины регистрируются один раз, на старте, а переключаются по id:

```ts
await engine.useProvider('psp')
await engine.pay({ input: { planId: 'monthly' }, instrument: card })
```

Со стороны вашего кода это вся разница между шестью совершенно разными интеграциями.

## Какой мне нужен?

Отталкивайтесь от того, что делает покупатель, а не от названия провайдера.

| Покупатель…                                    | Плагин                                       | Вводит карту на вашей странице? |
| ---------------------------------------------- | -------------------------------------------- | ------------------------------- |
| вводит карту, банк может попросить подтвердить | [Карточный процессинг](./psp.md)             | да                              |
| вводит карту, старый банк, прямая связь        | [Банк-эквайер](./acquiring.md)               | да                              |
| уходит на страницу банка                       | [Платёжная страница банка](./hosted-page.md) | нет                             |
| вводит карту во фрейм провайдера               | [Хостед-поля](./hosted-fields.md)            | нет                             |
| жмёт Apple Pay, Google Pay, PayPal             | [Кошелёк](./wallet.md)                       | нет                             |
| сканирует QR в банковском приложении           | [Банковский перевод](./bank-transfer.md)     | нет                             |

Последняя колонка важнее всего, и это не вопрос интерфейса. **Карта, введённая на вашей
странице, переводит вас в куда более длинную анкету PCI.** Хостед-поля и платёжная страница
существуют, чтобы сдвинуть эту границу; только они убирают вашу страницу с пути карты.

## Одни и те же три момента, всегда

Что бы вы ни выбрали, платёж проходит одни и те же три момента. Полезно понимать, на который из
них вы смотрите, когда что-то пошло не так.

```text
1. создание      Ваш бэкенд просит провайдера открыть платёж.
2. подтверждение Уходит инструмент. Провайдер отвечает одно из:
                   - готово (одобрено или отказ)
                   - пока нет: сначала сделай вот это  ──┐
3. шаг           ──────────────────────────────────────┘
                 Фрейм, редирект, шит кошелька, QR-код. Он завершается,
                 и провайдера спрашивают снова. Пока ответ не станет окончательным.
```

Шаг 3 — единственное, чем плагины отличаются. На каждой странице ниже написано, какой шаг
просит её провайдер и чем этот шаг заканчивается.

## Как подключить любой из них

До всего этого — [Настройка окружения](./setup.md): что установить, что импортировать и что
класть в `.env`. Всё это одинаково, какой бы плагин вы ни выбрали.

Три вещи, всегда в одном порядке.

**1. Настроить.** Каждый плагин экспортирует тип конфига. Импортируйте тип — этим же плагин
регистрирует свой id в системе типов, поэтому `defineProvider({ id: 'psp' })` проверяется:

```ts
import type { PspConfig } from '@checkout-kit/provider-psp'

const psp: PspConfig = { baseUrl: '/api', acsOrigin: 'https://acs.yourbank.example' }
```

**2. Зарегистрировать.** `load` — динамический импорт, поэтому каждый плагин это свой чанк, и
покупатель, который его не выбрал, ничего не скачивает. Тот, что показываете первым, пометьте
`eager`:

```ts
defineProvider({
  id: 'psp',
  config: psp,
  load: () => import('@checkout-kit/provider-psp'),
  eager: true,
})
```

**3. Дать браузерному рантайму то, что нужно этому плагину.** Большинству не нужно ничего.
Кошельку нужен адаптер к его SDK; плагину, который рисует фрейм, можно задать заголовок. См.
страницы ниже.

```ts
const runtime = createBrowserRuntime({ returnPath: '/payment/return' })
```

Полностью рабочая точка сборки со всеми шестью —
[`apps/demo/src/app/providers/checkout.ts`](../../../apps/demo/src/app/providers/checkout.ts).

## Как попробовать без провайдера

Все плагины написаны против мок-бэкенда из `@checkout-kit/testing`, поэтому все шесть
запускаются без аккаунтов и ключей:

```bash
npm run dev:mock   # демо с мок-бэкендом в браузере
npm run dev:bank   # симулятор 3-D Secure, для карточных сценариев
```

Исход решает карта. Вот те, что знает мок-бэкенд:

| Карта                 | Что произойдёт                       |
| --------------------- | ------------------------------------ |
| `4242 4242 4242 4242` | одобрение                            |
| `4000 0000 0000 0002` | отказ                                |
| `4000 0000 0000 9995` | отказ, недостаточно средств          |
| `4000 0025 0000 3155` | 3-D Secure, и он проходит            |
| `4000 0084 0000 1629` | 3-D Secure, и он не проходит         |
| `4000 0000 0000 9979` | ещё обрабатывается, завершится позже |

## Об одном стоит сказать честно

Эти шесть плагинов — референсные реализации. Они написаны против мок-бэкенда, и **ни один из
них не провёл настоящий платёж.** Они показывают, как выглядит плагин каждой формы, и проходят
conformance-набор; считайте их отправной точкой для своего, а не интеграцией, которую сегодня
можно направить на живого провайдера.

Если пишете плагин для провайдера, которого здесь нет, читайте
[Как написать платёжный плагин](../plugin-authoring.md), затем
[Настоящие провайдеры на нашем контракте](../real-world-providers.md).
