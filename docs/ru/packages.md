# Каталог пакетов

> [English](../packages.md)

Checkout kit разбит на 16 отдельных пакетов, поэтому ставить нужно только то, что используете. Обычному веб-приложению нужны:

- `core` — платёжный движок (нужен всегда);
- один пакет провайдера, например `provider-stripe`;
- `runtime-browser` — чтобы движок работал в браузере;
- `react` — если приложение на React 19;
- `ui` — если нужны готовые компоненты (необязательно).

В каждом архиве есть JavaScript (ESM), типы TypeScript и экспорты. Все архивы проверяются установкой в отдельный чистый проект.

## Основа и хосты {#checkout-and-hosts}

| Пакет                           | Что делает                                                                                                                                               | Руководство                      |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `@checkout-kit/core`            | Платёжный движок: типы платежей, список провайдеров, состояние, восстановление и HTTP-клиент. Без кода для браузера и без React.                         | [Архитектура](./architecture.md) |
| `@checkout-kit/runtime-browser` | Выполняет дополнительные шаги в браузере: перенаправления и фреймы, поля провайдера, SDK провайдеров, QR-коды. Плюс session storage и страница возврата. | [Браузер](./runtime.md)          |
| `@checkout-kit/react`           | Связка с React 19: провайдер контекста, хуки для чтения состояния и компонент, который показывает дополнительные шаги.                                   | [React](./react.md)              |
| `@checkout-kit/ui`              | Готовые компоненты оплаты (поля, состояния, раскладки). Их стили не влияют на остальную страницу.                                                        | [UI](./ui.md)                    |
| `@checkout-kit/webview-bridge`  | Для мобильных приложений: типизированные сообщения, команды из приложения, навигация и deep link. Части в приложении браузер не нужен.                   | [WebView](./webview.md)          |

## Адаптеры конкретных провайдеров {#named-provider-adapters}

Эти три пакета работают с настоящими провайдерами. Браузер обращается к **вашему** серверу, а сервер — к провайдеру. К каждому есть пример ввода данных карты через SDK провайдера, рабочий сервер, тестовые данные и браузерные тесты. Проверить всё на своём тестовом аккаунте (песочнице) всё равно нужно самостоятельно.

| Пакет / id                   | Чем платит покупатель и как проходит оплата                                                                                                                    | Руководство                     |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `provider-stripe` / `stripe` | Токен PaymentMethod из Stripe.js. Используются PaymentIntents, шаги SDK и перенаправления. Деньги списываются автоматически.                                   | [Stripe](./providers/stripe.md) |
| `provider-adyen` / `adyen`   | Зашифрованные данные из компонента Adyen, токен сохранённой карты или данные карты напрямую, если вы это разрешили. Advanced flow; состояние проверяет сервер. | [Adyen](./providers/adyen.md)   |
| `provider-paypal` / `paypal` | На вашей странице ничего не вводится. Покупатель подтверждает оплату в PayPal (Orders v2), потом ваш сервер списывает и проверяет платёж.                      | [PayPal](./providers/paypal.md) |

Названия всех пакетов начинаются с `@checkout-kit/`.

## Протоколы-примеры {#reference-protocols}

Эти пакеты — **рабочие шаблоны** для типовых платёжных API. Они общаются только со встроенным симулятором. Берите их за основу для своего провайдера. Сами по себе они не дают ни Apple Pay, ни Google Pay, ни подключения к настоящему банку, даже если протокол похож.

| Пакет / id                                | Показывает, как работать с                                     | Руководство                                    |
| ----------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------- |
| `provider-psp` / `psp`                    | JSON API, сохранёнными картами, 3DS2.                          | [PSP](./plugins/psp.md)                        |
| `provider-acquiring` / `acquiring`        | API банка на HTML-формах, числовыми статусами, 3DS1.           | [Эквайер](./plugins/acquiring.md)              |
| `provider-hpp` / `hpp`                    | Страницей оплаты на сайте провайдера и проверкой возврата.     | [Платёжная страница](./plugins/hosted-page.md) |
| `provider-hosted-fields` / `hostedfields` | Полями карты во фрейме провайдера, которые возвращают токен.   | [Поля провайдера](./plugins/hosted-fields.md)  |
| `provider-wallet` / `wallet`              | SDK кошелька и проверкой токена кошелька.                      | [Кошелёк](./plugins/wallet.md)                 |
| `provider-bank-transfer` / `transfer`     | Показом QR-кода или кода оплаты и ожиданием поступления денег. | [Перевод](./plugins/bank-transfer.md)          |

## Пакеты для разработки {#development-packages}

| Пакет                       | Что делает                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `@checkout-kit/testing`     | Тестовые карты, поддельные провайдеры и раннеры, поддельный платёжный сервер (MSW). Каждое импортируется отдельно.    |
| `@checkout-kit/conformance` | Готовый набор тестов Vitest для плагинов провайдеров. Проверяет повторы, повторные запросы и данные от чужого заказа. |

Подробнее — в разделе [тестирование](./testing.md). Никогда не используйте поддельный сервер как настоящий платёжный сервер.

## Установка и зоны ответственности {#installation-and-support-boundary}

В [быстром старте](./getting-started.md#install-package-archives) показано, как установить нужные архивы вместе с зависимостями. Комплект `0.2.0` (UI — `0.2.0`, остальные пакеты — `0.1.0`) лежит в [релизах GitHub](https://github.com/pavel-labs/checkout-kit/releases/tag/v0.2.0) вместе с установщиком, который сам добавляет нужные пакеты checkout-kit. Текущие настройки пакетов указывают на GitHub Packages; публикация в реестр настраивается отдельно. Архивы, собранные локально или в CI, работают сами по себе.

**Библиотека** проводит оплату на стороне клиента: шаги, повторы, восстановление.

**Ваш сервер** отвечает за:

- вход покупателя;
- цены;
- секретные ключи;
- хранение заказов в базе данных;
- то, что каждая операция выполняется только один раз (идемпотентность), даже при параллельных запросах;
- проверку уведомлений провайдера (вебхуков);
- выдачу заказа.

Подробнее — в разделе [сервер мерчанта](./merchant-integration.md).
