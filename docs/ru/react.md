# Оплата на React

> [English](../react.md)

`@checkout-kit/react` подключает платёжный движок к приложению на React 19. Он не заменяет API вашего сервера и ваши поля формы. Необязательный UI-кит даёт готовое оформление, но ваша собственная дизайн-система так же хорошо работает с теми же хуками.

## Полный небольшой пример {#complete-example}

Скопируйте два файла в свой проект под именами `quickstart-engine.ts` и `quickstart.tsx`. Это настоящие файлы из репозитория, их проверяет сборка TypeScript, поэтому они всегда рабочие. Ещё понадобятся [маршруты PayPal на вашем сервере](./providers/paypal.md). Создайте движок один раз в браузере и запустите приложение [этим кодом](./getting-started.md#connect-your-app).

Настройка движка:

<<< @/../examples/react/quickstart-engine.ts

Экран на React:

<<< @/../examples/react/quickstart.tsx

Как работает пример:

- цену назначает сервер по `planId`, а `Money` только показывает её;
- `PaymentActionHost` выполняет шаг подтверждения в PayPal;
- если результат неясен (например, оборвалась сеть), кнопка «попробовать снова» повторяет восстановление или ту же попытку, поэтому деньги не спишутся дважды;
- кнопка «начать заново» появляется только тогда, когда у платежа подтверждён окончательный статус.

## Сколько живёт движок {#engine-lifetime}

Создавайте **один** движок на одну оплату и **вне** отрисовки (не в теле компонента). Если создавать новый движок при каждой отрисовке, теряются подписки и платёж, который уже идёт.

Пока шаг выполняется, `PaymentActionHost` должен оставаться на экране. Если он пропадёт, шаг остановится.

- `CheckoutProvider` передаёт движок хукам внутри себя.
- `CheckoutRoot` добавляет CSS-тему, плотность и атрибуты платформы.

Если вместо `@checkout-kit/ui` у вас свой интерфейс, нужен только `CheckoutProvider`.

## Читайте только нужное состояние {#subscribe-to-the-state-you-need}

| Хук                                          | Что возвращает                                                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `useCheckoutEngine()`                        | Команды движка. Компонент не перерисовывается при смене состояния.                                                 |
| `useCheckoutSnapshot()`                      | Текущее состояние: фаза, платёж, шаг, ошибка, провайдер и его возможности.                                         |
| `useCheckout()`                              | Состояние плюс движок и флаги `isBusy`, `isSettled` и `isLocked`.                                                  |
| `useCheckoutSelector(selector, isEqual?)`    | Только выбранную вами часть. Перерисовка — только когда эта часть меняется. Можно передать свою функцию сравнения. |
| `usePaymentState({ isDirty, isValidating })` | Состояние, которое учитывает и вашу форму (изменена, идёт проверка).                                               |

```tsx
import { useCheckoutSelector } from '@checkout-kit/react'
const total = useCheckoutSelector(
  (s) => ({ amount: s.intent?.amount, currency: s.intent?.currency }),
  (a, b) => a.amount === b.amount && a.currency === b.currency,
)
```

Правила и подводные камни:

- селектор должен только читать данные, без побочных эффектов;
- `isSettled` значит «движок остановился». Сюда входят и ошибки, и неясный результат. Это **не** значит «оплачено»;
- `isLocked` тоже равен `true` в окончательных состояниях. Не отключайте кнопку повтора навсегда только по нему — добавьте своё условие для восстановления или новой попытки.

## Дополнительные шаги и восстановление {#actions-and-recovery}

- `PaymentActionHost` сам запускает шаг (`autoRun` включён по умолчанию).
- `surface` позволяет выбрать, где показывать шаг, если провайдер это поддерживает.
- `onSettled` — только для интерфейса: показать сообщение, перейти на другую страницу. Выдача заказа — задача сервера.
- При `autoRun={false}` вызывайте `engine.runPendingAction` сами и передавайте место для показа (mount).

Компонент не даёт запустить один и тот же шаг дважды, даже если провайдер присылает несколько шагов подряд с одинаковым id.

Компоненты React и UI можно рендерить на сервере (SSR), но браузерный runtime создавайте только в браузере. См. [работа в браузере](./runtime.md) и [решение проблем](./troubleshooting.md).
